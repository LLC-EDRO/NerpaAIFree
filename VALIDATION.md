# Проверка прототипа — 21 сентября 2026

## 23 сентября — исправления после пилота двух новых шаблонов

Область изменений: только `nerpa-test`, без подключения к базе и без генерации новых изображений в пилоте. Исходные файлы: `3 (2).pptx` (24 слайда) и `5 (1).pptx` (97 слайдов). Первая исходная попытка остановилась через 454,9 с на переполнении заголовка; вторая — через 174,6 с из-за памяти. Эти времена относятся к неуспешным попыткам, а не к готовым презентациям.

Подтверждённые причины и изменения:

1. **Переписывание текста не устраняло нехватку высоты строки.** У заголовка измеренная строка 27,5 pt при доступных 26,65 pt; автоматическое расширение не поддерживало центральную привязку. Добавлен отдельный вызов ИИ с исходным слайдом, текущими текстами, ошибкой, точными рамками и соседями. При наличии соответствующего текущему тексту неудачного рендера передаётся и он. ИИ предлагает координаты, сервер проверяет их и только затем применяет. В реальном повторе ИИ увеличил высоту на 2 pt симметрично, сохранив формулировку и шрифт; исходная ошибка исчезла.
2. **Изменение рамки не отменяло запрет старого текста.** Отклонённые варианты сохраняются, но ошибки старой геометрии больше не запрещают тот же текст после принятого изменения размеров. Предложения и отказы записываются отдельно; на неизменный макет допускается не более четырёх геометрических предложений, два последовательных отказа останавливают этот способ. Частично успешное расширение получает обратную связь для оставшихся полей.
3. **Большой шаблон раздувал служебную модель.** В нём 8653 объекта, включая 8136 пустых текстовых оболочек векторной графики. Parser JSON достигал 434 483 103 байт. Пустым декоративным объектам больше не копируются наследуемые текстовые стили; полные нативные объекты и исходный PPTX сохраняются. Запись выполняется потоком, повторяющиеся XML-фрагменты хранятся однократно, используется сжатый JSON-конверт с обратимым чтением и поддержкой старых файлов. Parser JSON этого шаблона стал около 10,77 MiB.
4. **Парсер и LibreOffice одновременно занимали память.** Docker подтвердил OOM, в том числе когда ошибка наружу выглядела как отказ рендера. Разбор теперь выполняется дочерним процессом, который завершается до запуска LibreOffice. Лимит 2 GiB не увеличивался. Реальный разбор и превью всех 97 слайдов завершились за 132,51 с; доступен 91 макет.
5. **Пустые ячейки теряли оформление при первом заполнении.** Измерение учитывало `endParaRPr`, а экспортёр создавал текст без этих свойств: Inter превращался в Arial, пропадало полужирное начертание. Теперь стиль вставки переносится в новый run, явные свойства исходного run имеют приоритет. Повтор рендера реальных таблиц больше не выдавал `rendered_font_mismatch`. Такие ошибки оформления не отправляются на бессмысленную перепись текста; финальный рендер остаётся обязательным.
6. **Проверка путала структуру с фактами.** Номера строк в подтверждённой колонке «№» больше не требуют веб-источников; произвольные числа, проценты и изменённые по смыслу колонки по-прежнему проверяются. В плане известные `evidence-N` исключаются из числовых утверждений. Отказ плана теперь перечисляет конкретные неподтверждённые числа и слайд.
7. **Неполный JSON исправлялся по слишком общей ошибке.** Ошибка сопоставления полей теперь содержит явные `missing` и `unexpected`; повторный запрос требует полный объект, включая последнюю строку таблицы. Проверяющему передаётся сетка любой таблицы, включая объединённые ячейки, для проверки связи строк, заголовков и показателей.
8. **Рендер проверял пересечения только редактируемых полей.** Добавлена проверка фактических букв относительно неизменяемого текста, включая колонтитулы и ссылки. Пустые рамки соседних объектов сами по себе не считаются перекрытием.
9. **Пустая схема ошибочно считалась заполненным содержательным макетом.** Соединённые пустые прямоугольные узлы без доступных полей выявляются до планирования. Такие макеты сохраняются для просмотра; планировщик выбирает другой макет того же шаблона. В новом плане первого пилота выбрано 10 разных макетов, без незаполненной схемы.


10. **Прозрачная рамка могла наследовать оформление.** Во втором шаблоне подпись не содержала локального `noFill`, хотя была прозрачной по цепочке master → layout → slide. Проверка теперь разрешает расширение только после подтверждения прозрачности всей цепочки; неизвестные эффекты и видимая заливка по-прежнему запрещены. ИИ расширил реальную подпись с 29,53 до 39,5 pt, после чего прежний текст прошёл проверку.
11. **Частичный успех слишком рано исчерпывал геометрические попытки.** Предложение исправило большинство рамок, но оставило две слишком низкими; следующая попытка обрезала нижнюю границу исходной рамки. Теперь в запросе есть явные `left/top/right/bottom`, текущая рамка и рекомендуемая высота из измерения. После частичного успеха разрешена дополнительная попытка в ограниченном бюджете; ИИ исправил координаты без ручного редактирования слайда.
12. **Пустой контейнер JSON вызывал ненужный повтор.** Только пустой `charts: []` нормализуется в `{}`. Непустой массив и отсутствие обязательных данных диаграммы по-прежнему являются ошибкой.

13. **Умещение не гарантировало понятный смысл.** На визуальной проверке второго результата обнаружены числа без единиц и названия регионов, сокращённые до букв. Проверяющий ИИ теперь различает необязательные подробности и утрату единицы/субъекта (`ambiguous_meaning`). Единицу разрешено перенести в связанную подпись или общий заголовок; не требуется повторять все факты плана. Общий заголовок не должен приписывать показатели разных технологий одной технологии. При смене версии этой политики заново проверяется смысл сохранённых слайдов, без обязательной переписи уже правильных текстов.

14. **Ошибочные смысловые группы запрещали правильное исправление.** Описание разбило число, регион и пояснение одной карточки на отдельные `group`. Исправляющий ИИ поэтому не мог перенести процент в связанную подпись. Для подозрительно одиночной метрики с отдельными подписями добавлен анализ связей по изображению и координатам. Он возвращает только группы существующих редактируемых ключей; пропуск, дубликат, чужой ключ или защищённый элемент отклоняются. Результат кэшируется в `semantic-groups-N.json`, исходное описание не подменяется, а уточнённые связи используются при заполнении и проверке. После изменения групп прежний текст проходит новую смысловую проверку.

15. **Локальная правка могла испортить сравнение между карточками.** При трёх и более существенных отказах исправляющий ИИ получает редактируемые поля всего слайда и задачу согласовать все блоки одновременно. Для этого запроса используется `reasoning_effort: medium` вместо обычного `low`. Защищённые поля не открываются, ошибки одних только ссылок не включают такой режим, число попыток остаётся ограниченным. Дублирование одного субъекта и показателя в независимых карточках сравнения проверяется как потеря смысла, а не принимается ради вместимости.

16. **Отступы узкой ячейки не оставляли места обычной цифре.** В нумерующей колонке шириной 39,69 pt боковые отступы занимали суммарно 28,8 pt. Цифра «2» не помещалась, и прежний принятый вариант содержал надстрочную «²». Добавлено минимальное уменьшение внутренних отступов только переполненной ячейки и только если неизменный текст после этого физически помещается. Сохраняются сетка таблицы, внешние размеры и шрифты; отступы не уменьшаются ниже 2 pt либо исходного меньшего значения. Экспорт применяет те же отступы после создания строк. Обновлена версия fit, чтобы старые отказы не запрещали повторную проверку обычной цифры.

Скрытый неизменяемый текст, перекрытый непрозрачным объектом исходного шаблона, не считается видимым препятствием. Завершение процесса конвертера с кодом -9/137 классифицируется как нехватка ресурсов, чтобы не тратить запросы модели на переписывание текста при системном отказе.

Границы механизма: ИИ не получает права произвольно перерисовать PPTX. Геометрические предложения ограничены поддерживаемыми прозрачными текстовыми рамками; таблицы, группы, защищённые элементы и сложные эффекты не растягиваются этим механизмом. Проверяются все соседние объекты, включая не вошедшие в компактный контекст модели. Нельзя уменьшать исходную область, выходить за страницу, создавать новые пересечения или менять шрифт. После геометрического исправления сохраняются проверки содержания и итогового PDF. Неподдерживаемый макет не превращается автоматически в новую нарисованную схему.

Автоматические проверки: 106 TypeScript-тестов, 88 Python-тестов, TypeScript build — прошли. Новые проверки покрывают безопасную геометрию, атомарный отказ при пересечении, сохранение текста после изменения рамки, обратимость хранения модели, пустые векторные объекты, стили пустых ячеек, нумерацию и отступы таблиц, ссылки в плане, пересечение колонтитула, распознавание пустых схем и безопасное уточнение смысловых групп.

## Что выявила проверка

- Старый парсер ориентировался на названия `slideN.xml` и `chartN.xml`. Исправление в тестовой копии: порядок по relationships, диаграммы по content type. Собранный и экспортированный PPTX теперь читаются обратно.
- В первой попытке планировщик выбрал процесс из трёх шагов для двух утверждённых действий. Семантический анализ добавил лишнее действие, и проверка содержания остановила выдачу. Промпты уточнены: описание шаблона не придумывает новый смысл, план учитывает число блоков. В проверенном финальном варианте макет третьего слайда **сменён вручную в редакторе** на подходящий. Автоматический выбор макетов на любых входных презентациях этой проверкой не доказан.
- Исходный номер страницы «10» сохранялся на втором выбранном слайде. Добавлена перенумерация при сборке и экспорте. Финальный PDF/PNG и XML содержат «02»; крупные показатели не затрагиваются.
- Линейное описание всех строк как обязательных заставляло модель добавлять текст. В описании теперь различаются обязательная строка группы и необязательные продолжения. Это правило требует дальнейшей проверки на разнообразных пользовательских файлах.

### Дополнительная проверка VK Education и веб-поиска

Проект `1ee637be-e413-4f48-879b-2caf060ceccf`, утверждённая версия 2, девять выбранных слайдов из пользовательского файла VK Education. Исходная ошибка сохранена в `diagnostics-before-speaker-fix/` внутри каталога проекта.

- Причина первого сбоя: описание сделало поле имени/должности спикера обязательным при отсутствии таких данных. Утверждённый план требовал тематический подзаголовок. Добавлено согласование этой подписи с планом, включая ранее сохранённые контракты; геометрия и ключи не меняются.

- **Временный сбой модели или поиска.** Общий `provider-request.ts` делает до трёх попыток при разрыве передачи, некорректном JSON транспортного ответа и HTTP 408/409/429/500/502/503/504. Отмена пользователя прерывает ожидание и запрос. Журнал восстановления не содержит ключей и тела ошибки провайдера.
- **Обрезанный ответ модели.** Вместо немедленного `llm_truncated` выполняется одна повторная генерация компактного полного JSON с увеличенным лимитом ответа. Обрезанный многотысячный ответ не добавляется во входной контекст. Существующая коррекция схемы JSON сохранена; максимум — три ответа на один логический вызов. Отказ модели не обходится. - **Незавершённый веб-поиск.** Использует существующий общий бюджет до трёх поисковых проходов; ранее найденные факты с цитатами сохраняются. Это не разрешает выдумывать числа или выдавать пустую метрику. Завершённый поиск с небольшим или пустым корпусом кэшируется по теме/плану/требованиям и не повторяется на каждом рендер-исправлении. Бесконечный цикл и повторная выдача отвергнутого текста не разрешены.

Максимум — две попытки; ошибки формата, повреждённые связи, неподдерживаемая структура и превышение ресурсов не объявляются временными. Дублирующий внешний повтор экспорта удалён.

## 2026-09-24 — нумерация выбранных слайдов

Причина: page_numbers.py принимал только одиночное число, совпадающее с исходным индексом. Формат «07 / 16» не распознавался. Кроме того, перенумерация происходила до подстановки текста и могла быть перезаписана при заполнении.

Исправление: обработка одиночных номеров, номера/общего количества, подписей «Слайд N из M»/«Page N of M» и явных полей PowerPoint; сохранение ведущих нулей по соседним полям нумерации. Правка диапазонов цифр внутри исходных a:t сохраняет разделители, отдельные текстовые runs, шрифты, цвета и расположение. Распознавание обычных полей ограничено нижними небольшими надписями и признаками нумерации; статистика внутри слайда не меняется. Для сгруппированных полей учитывается масштаб и смещение группы. Обновление выполняется при сборке выбранных макетов и повторно после всех изменений финального слайда. В финальную сборку передаются реальный ordinal, deckSlideCount и индекс исходного макета также для восстановленных AI-слайдов. Без поля нумерации новое поле не добавляется.
